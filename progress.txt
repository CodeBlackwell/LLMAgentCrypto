# Progress Log

## Learnings
(Patterns discovered during implementation)
- The trading_lab.db file persists between runs and doesn't auto-migrate. When adding new columns, delete the db file to recreate schema.
- Tests use in-memory SQLite via fixtures, but the app may init the real db first. The `override_db` fixture patches the database module.
- No mypy in project - uses ruff for linting. Import verification via python -c is sufficient for typecheck.

## Iteration 7 - US-007: Add SSE streaming endpoint
- What was implemented:
  - Added GET /backtests/{backtest_id}/stream endpoint in trading_lab/api/routes/backtests.py
  - StreamingResponse with media_type="text/event-stream" and Cache-Control/Connection headers
  - Emits event types: progress (progress updates), trades (new trades), complete (success), error (failure)
  - Polls database every 500ms (asyncio.sleep), emits only on changes (tracks last_progress_percent, last_trade_count)
  - Auto-closes stream when status is terminal (completed or failed)
  - Removed unused ErrorResponse import (pre-existing lint issue)
- Files changed:
  - trading_lab/api/routes/backtests.py
  - PRD.md (marked task complete)
- Learnings for future iterations:
  - Use AsyncGenerator[str, None] for SSE streaming generator functions
  - TradeRepository.list_for_backtest() returns trades for a given backtest_id
  - SSE format: "event: {type}\ndata: {json}\n\n"
  - All 227 tests continue to pass
